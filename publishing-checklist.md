# Public publishing checklist

Before making the repository public:

- [ ] Confirm you are allowed to publish code derived from employer/client work.
- [ ] Keep only fictional brand names and synthetic data.
- [ ] Search the repo for client names, employee names, campaign names, account IDs, spreadsheet IDs, tokens, and URLs.
- [ ] Do not publish platform credentials, OAuth secrets, API tokens, cookies, or connector configurations.
- [ ] Do not upload the original production spreadsheet.
- [ ] Use an anonymized or synthetic screenshot rather than the original dashboard screenshot if it contains confidential spend or brand data.
- [ ] Decide on a software license only after confirming code ownership.
- [ ] In the README, describe upstream platform ingestion accurately; the supplied code starts from the normalized Google Sheets layer.
